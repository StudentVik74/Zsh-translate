## Что такое uv и зачем он нужен

**`uv`** — это менеджер пакетов и виртуальных окружений для Python.
Разработан компанией [Astral](https://astral.sh/) (те же люди,
что сделали линтер `ruff`).

### Что он заменяет

| Старый инструмент | Что делал | Замена в uv |
|---|---|---|
| `pip` | устанавливал пакеты | `uv add`, `uv pip install` |
| `venv` | создавал виртуальное окружение | `uv venv` (автоматически) |
| `pip-tools` | фиксировал версии зависимостей | `uv lock` |
| `poetry`, `pdm` | управляли проектом целиком | сам `uv` |
| `pyenv` | ставил разные версии Python | `uv python install` |

### Почему это удобно

1. **Скорость.** `uv` в 10–100 раз быстрее `pip`. Установка зависимостей
   занимает секунды вместо минут.
2. **Один инструмент** вместо пяти. Не надо помнить `pip`, `venv`,
   `pip-tools`, `pyenv` — всё в одной команде.
3. **Воспроизводимость.** Файл `uv.lock` фиксирует точные версии всех
   пакетов. Один и тот же проект на разных машинах ставится одинаково.
4. **Работает на Windows, Linux, macOS.** Не надо возиться с
   `python3 -m venv` и активацией скриптов под разные ОС.

### Что это даёт в нашем проекте

- **Один раз** поставили `uv` — и забыли о проблемах с зависимостями.
- **Тесты работают одинаково** у всех: `uv run pytest`.
- **CI на GitHub** использует тот же `uv` — что локально, то и в облаке.
- **Новому разработчику** достаточно `uv sync` — и всё готово.

## Установка uv

### Linux / macOS

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

После установки перезапустите терминал или выполните:

```bash
source $HOME/.local/bin/env
```

### Windows (PowerShell)

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

После установки закройте и откройте PowerShell заново.

### Проверка

```bash
uv --version
```

Ожидаемо: `uv 0.11.x` или похожее.

**Если команда не найдена** — убедитесь, что папка с `uv` в `PATH`.
Обычно:
- Linux/macOS: `~/.local/bin/`
- Windows: `%USERPROFILE%\.local\bin\`

## Быстрый старт

Три команды — и вы готовы работать:

```bash
git clone https://github.com/StudentVik74/Zsh-translate.git
cd Zsh-translate
uv sync
```

Всё. `uv sync`:

- создаст виртуальное окружение `.venv/` в папке проекта;
- скачает и установит все зависимости из `uv.lock`;
- **установит сам проект** в editable-режиме — появится команда `ru`
  (см. `[project.scripts]` в `pyproject.toml`).

Проверьте, что всё работает:

```bash
uv run ru -t "hello"
# → привет
```

Если увидели `привет` — вы готовы. 🎉

## Основные команды

Шпаргалка по самым частым командам `uv`.

| Команда | Что делает |
|---|---|
| `uv sync` | Установить всё из `uv.lock` |
| `uv run <команда>` | Запустить команду в окружении проекта |
| `uv add <пакет>` | Добавить зависимость в проект |
| `uv add --dev <пакет>` | Добавить dev-зависимость (тесты, линтеры) |
| `uv remove <пакет>` | Удалить зависимость |
| `uv lock` | Обновить `uv.lock` (пересчитать версии) |
| `uv lock --upgrade` | Обновить все пакеты до последних версий |
| `uv python install 3.12` | Установить конкретную версию Python |
| `uv python list` | Список доступных версий Python |
| `uv tree` | Показать дерево зависимостей |
| `uv cache clean` | Очистить кэш пакетов |
| `uv self update` | Обновить сам `uv` |

**Все команды** запускаются **из корня проекта** — там, где лежит
`pyproject.toml`.

## Как запускать проект

### Способ A. Через `uv run` (без активации)

```bash
uv run ru -t "hello"
uv run ru ls -la /nonexistent
uv run ru docker --help
echo "Something went wrong" | uv run ru
```

`uv run` **автоматически**:
1. Проверяет, что `.venv/` синхронизировано с `pyproject.toml`.
2. Доустанавливает недостающие пакеты (если что-то менялось).
3. Запускает команду в этом окружении.

**Плюс:** не нужно активировать venv вручную. Просто добавьте
`uv run` перед любой командой.

### Способ B. После активации venv

```bash
# Linux / macOS
source .venv/bin/activate

# Windows (PowerShell)
.venv\Scripts\Activate.ps1

# Windows (cmd)
.venv\Scripts\activate.bat
```

После активации можно запускать `ru` **напрямую**, без `uv run`:

```bash
ru -t "hello"
ru docker --help
```

Признак активного окружения — `(.venv)` в начале строки приглашения:

```
(.venv) user@machine:~/Zsh-translate$
```

Деактивировать: `deactivate` (в любой ОС).

### Что выбрать

| Ситуация | Способ |
|---|---|
| Разово запустить что-то | **A** — `uv run ...` |
| Много работать в проекте | **B** — активировать и забыть |
| CI, скрипты | **A** — явно видно, что используется uv |
| Знакомы с `venv` из прошлого опыта | **B** — привычно |

## Как запускать тесты

```bash
# Все быстрые тесты (без сети)
uv run pytest

# Подробный вывод — какое имя теста, статус
uv run pytest -v

# С покрытием
uv run pytest --cov=utils --cov-report=term-missing

# Только конкретный файл
uv run pytest tests/test_process.py -v

# Только конкретный тест
uv run pytest tests/test_process.py::test_process_uses_cache -v

# Только интеграционные (реальный MyMemory API, тратят квоту)
uv run pytest -m integration
```

`uv run pytest` работает **без** предварительной активации venv.

**Остановить на первой ошибке:** `uv run pytest -x`
**Показать stdout/stderr:** `uv run pytest -s`

Подробнее о тестах — в [tests/README.md](../tests/README.md).

## Работа с зависимостями

### Добавить обычную зависимость

```bash
uv add requests
```

Что произойдёт:
- пакет добавится в `[project].dependencies` в `pyproject.toml`;
- версия зафиксируется в `uv.lock`;
- пакет сразу установится в `.venv/`.

### Добавить dev-зависимость

Для инструментов разработки — тестов, линтеров, форматтеров:

```bash
uv add --dev pytest pytest-mock pytest-cov
```

Они попадут в секцию `[dependency-groups].dev` и **не будут**
устанавливаться у конечных пользователей, если пакет публикуется
на PyPI.

### Удалить зависимость

```bash
uv remove requests
```

### Обновить все зависимости до последних версий

```bash
uv lock --upgrade
uv sync
```

### Установить точные версии из `uv.lock` (например, после `git pull`)

```bash
uv sync
```

Это **безопасная операция** — она приводит `.venv/` в состояние,
описанное в `uv.lock`.

## Файлы, которые создаёт uv

### `pyproject.toml`

Главный конфиг проекта. Здесь указываются:

- **метаданные** — имя, версия, описание, лицензия;
- **зависимости** — что нужно проекту;
- **dev-зависимости** — что нужно только для разработки;
- **`[project.scripts]`** — какие команды создать при установке
  (у нас — `ru`);
- **настройки инструментов** — `pytest`, `ruff` и т.д.

Пример из нашего проекта:

```toml
[project]
name = "zsh-translate"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = ["requests"]

[project.scripts]
ru = "utils.translate:main"

[dependency-groups]
dev = [
    "pytest>=8.1.1,<9",
    "pytest-mock>=3.14.0",
    "pytest-cov>=6.0.0",
]
```

### `uv.lock`

**Файл блокировки.** Фиксирует **точные версии** всех пакетов — включая
транзитивные (зависимости зависимостей).

Зачем нужен:
- воспроизводимость — на другой машине встанут **те же** версии;
- безопасность — если злоумышленник выпустит вредоносную версию
  пакета, ваш проект её **не подхватит** до явного обновления.

⚠️ **`uv.lock` коммитится в git.** Не добавляйте его в `.gitignore`.

### `.venv/`

Виртуальное окружение — папка с установленным Python и всеми пакетами.

⚠️ **`.venv/` НЕ коммитится в git.** Уже в `.gitignore`.

Если удалить `.venv/`, восстановится командой `uv sync`.

### `.python-version`

Файл с версией Python, которую использует проект (у нас — `3.12`).
Нужен, чтобы `uv` автоматически ставил правильную версию.

Если его нет — `uv` создаст при первом `uv sync`.

## Частые проблемы

### `uv: command not found`

`uv` не в `PATH`. Решения:

**Linux/macOS:**
```bash
source $HOME/.local/bin/env
```
Или добавьте в `~/.zshrc` / `~/.bashrc`:
```bash
export PATH="$HOME/.local/bin:$PATH"
```

**Windows:** закройте и откройте PowerShell. Если не помогло:
```powershell
$env:Path = "$env:USERPROFILE\.local\bin;$env:Path"
```
И перезапустите.

### `Failed to download Python 3.12`

`uv` не смог скачать Python. Проверьте интернет:

```bash
curl -sS -o /dev/null -w "%{http_code}\n" https://python.org
```

Если не `200` — сеть блокирует. Решение: установите Python 3.12
вручную и в `pyproject.toml` замените `requires-python` на версию,
которая у вас есть.

### `Cannot find pyproject.toml`

Вы не в корне проекта. Проверьте:

```bash
pwd
ls pyproject.toml
```

Перейдите в корень:

```bash
cd /path/to/Zsh-translate
```

### `uv sync` падает с `Permission denied`

Возможно, у `.venv/` неправильные права. Удалите и пересоздайте:

```bash
rm -rf .venv
uv sync
```

Windows (PowerShell):
```powershell
Remove-Item -Recurse -Force .venv
uv sync
```

### `uv run ru` не находит команду `ru`

Проект не установлен как пакет. Проверьте в `pyproject.toml`:

- есть ли секция `[project.scripts]` с `ru = "utils.translate:main"`;
- есть ли файл `utils/__init__.py`;
- есть ли `[build-system]` в `pyproject.toml`.

Затем:

```bash
uv sync --reinstall
```

### `ModuleNotFoundError: No module named 'utils'`

Нет файла `utils/__init__.py`. Создайте:

```bash
touch utils/__init__.py
uv sync
```

### `uv run pytest` не находит pytest

Dev-зависимости не установлены. Выполните:

```bash
uv sync --dev
```

Или добавьте `--dev` при установке:

```bash
uv add --dev pytest
```

## Итог

Для повседневной работы в проекте нужно помнить **три команды**:

```bash
uv sync                  # установить/обновить зависимости
uv run <команда>         # запустить что-то в окружении проекта
uv add --dev <пакет>     # добавить инструмент разработки
```

Этого достаточно, чтобы:
- клонировать проект на новой машине и сразу начать работу;
- запускать тесты;
- добавлять и убирать зависимости;
- не думать о `pip`, `venv` и конфликтах версий.

Если что-то не работает — спросите в **Issues** проекта.
